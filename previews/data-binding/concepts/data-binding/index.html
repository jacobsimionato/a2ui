Data Model and Data Binding

In A2UI, the component hierarchy of a surface is decoupled from its runtime state. Every surface owns an isolated, reactive JSON object tree called the DataModel.

Components bind their properties to locations inside the DataModel using RFC 6901 JSON Pointers (such as /reservation/guestEmail or /invoice/total). When either the agent or the user mutates a path in the DataModel, only the specific widgets subscribed to that path re-render.

Populating the data model

A surface DataModel can be populated through two complementary paths:

  1. Deterministic tool and backend data injection: An agent runtime, server, or tool handler can populate structured data directly into the surface’s DataModel using updateDataModel. When an external tool returns live database rows, flight availability, or price calculations, the host application injects that data payload directly into target pointers (for example, /flights or /invoice/total) without forcing a large language model to serialize and echo the records into its text output stream. This approach prevents hallucinated fields and conserves output tokens.
  2. Model-generated state: A language model can define initial data values inline within createSurface or emit subsequent updateDataModel messages to modify state during a conversational turn.

Because UI layout (updateComponents) and data payloads (updateDataModel) are transmitted as distinct messages, an agent can emit a shared component template once and update data payloads dynamically at any point during a session.

Upsert and deletion semantics (updateDataModel)

When the client renderer receives an updateDataModel message (or UpdateDataModelMessage in v0.9.1), it applies upsert semantics at the target JSON Pointer path:

  1. Root replacement: Omitting path (or providing "path": "/") replaces the entire DataModel object of the surface.
  2. Targeted path update: Providing a pointer such as "path": "/invoice/total" creates any missing intermediate objects and updates only that specific leaf value.
  3. Key deletion: In v1.0, setting "value": null removes the key at path from its parent object. In v0.9.1, omitting the value property deletes the key.

  • v0.9.1 (Current)

Core data binding patterns

Component properties typed as dynamic values (DynamicString, DynamicNumber, DynamicBoolean, DynamicStringList, or DynamicValue) accept three forms:

  1. A static literal value (such as "Alex" or 42).
  2. A reactive DataBinding pointing to a path in the DataModel ({"@path": "/path"} in v1.0, {"path": "/path"} in v0.9.1).
  3. A catalog function call ({"@call": "fnName", "args": {...}} in v1.0, {"call": "fnName", "args": {...}} in v0.9.1).

Pattern 1: Two-way input binding and action context

Interactive input components bind their value property to a DataModel path. As the user enters text in a TextField or toggles a CheckBox, the renderer mutates that path in the local DataModel immediately.

When the user triggers an action (such as clicking a submit Button), the button’s action.event.context resolves those JSON Pointers and sends the current values to the agent in an action message:

Pattern 2: Reactive formatting and string interpolation (@call and formatString)

Component properties can bind to local catalog functions whose arguments reference DataModel pointers. When an underlying path in the DataModel changes, the Core SDK re-evaluates the function and updates the bound widget property.

For combining text with dynamic paths or nested function calls, use the Basic Catalog function formatString with ${...} interpolation placeholders:

  • v0.9.1 (Current)

Pattern 3: Local control-to-control synchronization

Because the DataModel is backed by reactive state signals on the client, two or more components bound to the same JSON Pointer stay synchronized locally without network round-trips.

Pattern 4: Collection scopes and dynamic list templates (ChildList and @index)

Container components whose children property uses ChildList (List, Row, Column) can either list static child component IDs (["item1", "item2"]) or bind to an array in the DataModel using a template object:

Protocol rule: ChildList uses path in both v0.9.1 and v1.0

Unlike property bindings that use “@path” in v1.0, the ChildList schema definition in common_types.json#/$defs/ChildList uses the literal property key “path” in both v0.9.1 and v1.0. Do not replace “path” with “@path” inside a ChildList template object.

When a container uses a template object, the Core SDK establishes a scoped DataContext for each item in the array at /addons:

  1. Relative JSON Pointers: Paths without a leading slash (such as {"@path": "title"} or {"@path": "price"}) resolve relative to the current array item (for example, /addons/0/title).
  2. Absolute JSON Pointers: Paths with a leading slash (such as {"@path": "/invoice/currency"}) resolve from the root of the surface DataModel.
  3. Current element index (@index): In v1.0, calling the built-in system function {"@call": "@index"} returns the zero-based integer index of the current template instance. It resolves to the innermost enclosing template scope and accepts an optional offset parameter ({"@call": "@index", "args": {"offset": 1}}) for one-based numbering.

Synchronizing state back to the agent (context vs. sendDataModel)

Local two-way data bindings do not stream individual keystrokes or slider movements across the network. State returns from the client renderer to the agent only when an interaction triggers an outbound message (action or callAgentFunction), using one of two mechanisms:

MechanismConfigurationWhen to use
Explicit action context (action.event.context)Declare a context map on the component’s action.event containing the specific @path pointers needed for that action.Default pattern. Keeps network payloads minimal; the agent receives only the fields relevant to the triggered action.
Full surface state (sendDataModel: true)Set "sendDataModel": true inside the createSurface message.Form wizards or stateful sessions where the agent expects the complete surface DataModel attached to every outbound client message (a2uiRendererDataModel in v1.0, or a2uiClientDataModel in v0.9.1).

Multi-agent privacy boundary

When "sendDataModel": true is enabled on a surface, the client renderer attaches that surface’s DataModel snapshot strictly to messages routed to the agent that created the surface, not broadcasting surface state to other agents.
