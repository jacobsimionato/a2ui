Data Model and Data Binding

In A2UI, the component hierarchy of a surface is decoupled from its runtime state. Every surface owns an isolated, reactive JSON object tree called the DataModel.

Components bind their properties to locations inside the DataModel using RFC 6901 JSON Pointers (such as /reservation/guestEmail or /invoice/total). When either the agent or the user mutates a path in the DataModel, only the specific widgets subscribed to that path re-render.

Upsert and Deletion Semantics (updateDataModel)

When the client receives an updateDataModel message, it applies upsert semantics at the target JSON Pointer path:

  • Root replacement: Omitting path (or setting "path": "/") replaces the entire DataModel object of the surface.
  • Targeted path update: Providing a pointer such as "path": "/invoice/total" creates any missing intermediate objects and updates only that leaf.
  • Key deletion: In v1.0, setting "value": null (or omitting value in v0.9.1) removes the key at path from its parent object.

  • v0.9.1 (Current)

Core Data Binding Patterns

Any component property typed as a dynamic value (DynamicString, DynamicNumber, DynamicBoolean, DynamicStringList, or DynamicValue) can accept a static literal, a JSON Pointer binding (@path in v1.0, path in v0.9.1), or a catalog function call (@call in v1.0, call in v0.9.1).

Pattern 1: Two-Way Input Binding & Action Context

Interactive input components bind their value property to a DataModel path. As the user types into a TextField or toggles a CheckBox, the renderer mutates that path in the local DataModel immediately.

When the user clicks a submit Button, the button’s action.event.context resolves those JSON Pointers and sends the current values to the agent:

Pattern 2: Reactive Formatting & String Interpolation (@call & formatString)

Component properties can bind to local catalog functions whose arguments reference DataModel pointers. Whenever the underlying path in the DataModel changes, the Core SDK automatically re-evaluates the function and updates the bound widget property.

For combining text with dynamic paths or nested function calls, use the Basic Catalog’s formatString(value) function with ${...} interpolation placeholders:

  • v0.9.1 (Current)

Pattern 3: Local Control-to-Control Synchronization

Because the DataModel is backed by reactive signals on the client, two or more components bound to the same JSON Pointer stay synchronized locally without network round-trips.

Pattern 4: Collection Scopes & Dynamic List Templates (ChildList & @index)

Container components whose children property uses ChildList (List, Row, Column) can either list static child component IDs (["item1", "item2"]) or bind to a DataModel array using a template object:

When a container uses a template object, the Core SDK creates a scoped DataContext for each element in the array at /addons:

  • Relative JSON Pointers (paths without a leading /, such as {"@path": "title"} or {"@path": "price"}) resolve relative to the current array item (/addons/0/title, /addons/1/title, etc.).
  • Absolute JSON Pointers (paths with a leading /, such as {"@path": "/invoice/currency"}) continue to resolve from the root of the surface DataModel.
  • Current Element Index (@index): In v1.0, calling the built-in system function {"@call": "@index"} returns the 0-based integer index of the current template instance. It resolves to the innermost enclosing template scope, and accepts an optional offset parameter ({"@call": "@index", "args": {"offset": 1}}) for 1-based numbering.

Synchronizing State Back to the Agent (context vs. sendDataModel)

Local two-way data bindings never stream individual keystrokes or slider movements across the network. State returns from the client renderer to the agent only when an interaction triggers an outbound message (action or callAgentFunction), using one of two mechanisms:

MechanismHow to ConfigureWhen to Use
Explicit Action Context (action.event.context)Declare a context map on the interactive component’s action.event containing the specific @path pointers needed for that action.Recommended default. Keeps payloads compact and explicit; the agent receives only the fields relevant to the triggered action.
Full Surface Sync (sendDataModel: true)Set "sendDataModel": true inside the createSurface message when creating the surface.Multi-step wizards or complex forms where the agent wants the complete surface dataModel attached automatically to every outbound client message.

Multi-Agent Privacy Boundary

When "sendDataModel": true is enabled on a surface, the client renderer attaches that surface’s dataModel snapshot strictly to messages routed to the agent that created the surface—never broadcasting surface state to unrelated third-party agents.
